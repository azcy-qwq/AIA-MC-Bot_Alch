## 第三方 /dig 附魔错误

用户确认服务由他人提供，本项目不能修改远端服务。核对公开源码后，远端 /dig 会调用 bestHarvestTool 扫描背包；仅切换主手不足以保证绕开附魔格式错误。

本地 C++ 仅针对 dig 返回的 `enchantments is not iterable` 尝试一次兼容恢复：

1. 确认有普通镐，或本地配方检查确认普通石镐原料齐全。
2. 寻找近处可用箱子，或使用现有备用箱子在无需挖掘的安全位置放置。
3. 使用公开容器 API 只暂存附魔物品，回读背包与箱子确认，持久化暂存坐标与清单。
4. 装备普通镐，再重试同一个 dig；不丢弃装备，不把武器放入副手。
5. 无法安全恢复或重试仍失败，报告 `api_compatibility_unresolved`。Distribution 保留失败工作并停止无效模型重试，人工提示可触发一次重试；Tac 继续监控。

鱼骨顺手采矿不再吞掉这类硬错误，仅跳过明确可恢复的局部空间问题。
