# 本轮手动改进：战术参考、持续作业与 Tac

本轮为手动项目开发，没有恢复六小时调试会话或新增自动化。

## 战术与调度

`docs/tactical-guide.txt` 是用户桌面 tac.txt 的原文副本，随项目保存。Strategy 的上下文包含 `primaryTacticalReference`，以首日木材/食物、地下据点、鱼骨采铁、装备升级为主要路线；Y=40/Y≈10 保留为用户建议，不当作地形或矿物生成保证。主世界等待、不提前进入下界的约束继续有效。Strategy 最短刷新和独立计时均为 240000ms，不因 Distribution 的强制刷新而提前触发。旧版本的长期路线会在首次启动重新生成，后续仍可恢复记忆和当前版本路线。

Distribution 分发一个大型作业动作，由脚本持续执行。目标为背包总数量，不是额外采集数量；只有实际物品入包才计入资源进展。Distribution 统一在当前任务预计剩余不超过4秒时提前规划一次；不再按80%进度、动作开始或周期计时反复请求。采集按本轮实际入包速率、挖掘速率及时间预算估算剩余时间，已有库存不计入本轮速率；普通动作仅在队列末尾且有同类动作的实测耗时可参考时预想下一步。无法估算时等结束/失败再生成，已有下一份计划则不重复生成。4秒是估计触发窗口，模型响应耗时不保证在该窗口内完成。Strategy 仍可在后台按4分钟周期规划。

## 可调用动作

```json
{"type":"chop_tree","params":{"targetCount":32,"maxDurationMs":240000}}
{"type":"mine_vein","params":{"types":["iron_ore","deepslate_iron_ore"],"targetCount":16}}
{"type":"fishbone_mine","params":{"types":["iron_ore","deepslate_iron_ore"],"targetCount":32,"direction":"z","length":24,"branchLength":5,"branchEvery":3,"maxBlocks":256}}
```

砍树/矿脉循环为重新观察、检查工具/背包、搜索目标、选择可站立位置、寻路、挖掘、核实入包；未发现目标时做有活动半径和次数限制的地形探索。鱼骨作业在当前实际高度逐段向前、进入支巷、返回主巷，不会隔着长距离远程挖掘，也不会自动挖到一个指定 Y。进入矿层可直接调用阶梯技能，不要求最近某次寻路失败；技能仍可先尝试直接到达它自己的目标。

脚本使用公开赛事 API；未加载/未知方块不会被当作空气。停机、死亡和 Tac 抢占会取消作业，取消后不会进入下一子动作。脚本直接复用执行器检查过的子操作，避免把自身子操作排到自己的队尾造成死锁。达到时间、挖掘、活动半径、连续无掉落或环境安全边界时停止，并向 Distribution 返回实际进展。背包满时停止重新分发整理，不擅自选择箱子丢弃物资。

## 空间经验固化

普通 move_to 和锚点路线中的移动会检查 Y-1 支撑、脚部格和头部格。等价目标优先同高/近高，不把矿物或树干坐标直接当作站立坐标。`exact:true` 为精确施工禁止换落脚点；非法精确位置直接拒绝。锚点之间调用统一 x/y/z 接口参数，保留原有途经点合法性检查和至少5格间距规则。实际移动结果不满足目标时仍返回失败。

## Tac

传统危险阈值触发后：抢占并停止旧作业 → 第一时间调用约1秒的攻击脚本 → 格挡/撤离/恢复。没有可见近身目标时攻击脚本立即返回，不为岩浆、溺水或伤害事件追击远处怪物。不可见目标短暂记为不交战。

末影人、僵尸猪灵等中立生物，以及白天普通蜘蛛，不因接口标记为 hostile 就自动引战；只有明确 angry/aggressive 或近期伤害来源证据才允许程序将其判作近身威胁。

快速模型只复核有风险线索的场景；场景变化时最短8秒，稳定风险30秒，安全稳定时不发请求。每次请求最多3秒，使用独立 Tac 对话通道，不卡住程序应急首招。模型只能建议枚举策略，不能发任意 API 参数。立即的程序保活与模型判断并行。

保活脚本支持已验证落脚点撤离、举盾、进食、威胁方向放一个障碍并保留其他出口，以及地板/顶板稳定时的三格侧向临时掩体。这里用侧向掩体替代盲目竖直挖脚下；保持两格人体净空，有食物或恢复条件才临时封一格，观察恢复后拆开封口。未知边界、液体或塌落风险不施工。未经过真实战斗场景完整验收。

常规战斗已取消后退控距，也忽略旧模型回复中的 spacing。保留短促攻击、攻击间隙举盾，以及低血/苦力怕时的应急撤离。

根据新版公开 API 文档，跳砍可通过 `/control {"jump":true,"ms":100}` 起跳，再观察 `/status.velocity[1]` 为负、且未落地后 `/look {"entity_id":...}` 对准目标，最后 `/control {"hit":true,"ms":50}` 单次挥砍。hit 是 /control 的参数，没有独立 /hit 端点。脚本只在近距离、地面、非液体、支撑和头顶余量已确认、生命至少10时尝试；苦力怕不跳砍。未满足条件或服务未部署该接口则回退普通攻击，等待下落的时间有上限。整个跳砍占一个队列工作，Tac/停机可取消，不插入其他普通工作。命中/暴击由服务端结算，下落观测不代表实际命中时仍在下落，因此不保证暴击。左键方块继续用 dig，右键用 interact。

接口来源：[新版 API](https://github.com/Zyzzyva0381/mc-agent-api/blob/main/docs/API.md)、[control/look 实现](https://github.com/Zyzzyva0381/mc-agent-api/blob/main/src/session.js)。本地旧文档未包含这些接口，现已同步公开新版。

## 调试界面

Strategy 和 Distribution 分别读自己的输出与输入，不再用历史 Strategy 填充空 Distribution。显示各自时间戳、任务执行/完成状态，以及大型脚本阶段、入包数量、挖掘数量。运行流程新增工作队列，直接读取执行器当前动作及有序待执行动作，并单列已准备的下一任务和待应用调整，显示来源、参数与入队/开始时间。Tac 模型调用和决策单列在 Tac，Token 按 Tac 计入正常合计，Reflection 继续单独统计。

## 本轮验证范围

仅做定向场景验证及语法检查，没有反复运行完整测试集。已验证单任务持续采集、按实际入包停止、Tac 取消循环、逐段鱼骨施工、等价落脚点同高优先/两格净空、应急攻击脚本先行、风险复核节流、中立目标过滤，以及分层调度和调试数据。

真实运行确认 Strategy 上下文带原文战术表、refreshIntervalMs=240000，Distribution 发出一个 chop_tree，脚本自行移动和多次挖掘并增加背包原木。随后近敌事件取消了脚本，Tac 进行了短促攻击和撤离，但角色仍在战斗中死亡并重生。因此不能宣称实战保活可靠或已完成32原木；实际死亡也促使本轮增加中立生物过滤。Tac 回包出现 responses 字符串时程序已统一成白名单数组，urgent 只接受布尔 true。

## 本轮导航更新

阶梯、搭桥、梯子与 navigation_recover 已取消最近一次 move_to/route_navigate 失败的执行门槛，提示词同步取消旧限制。阶梯遇到 air/cave_air 净空跳过挖掘；下一格脚下为空气时，仅在有材料、有附着面的情况下补足支撑并重新观察验证，再移动。没有材料、没有附着面、未知格、液体或 void_air 时停止，不把空气当作落脚面。

装备保护：Distribution 曾为绕过 enchantments is not iterable 将 iron_axe 放入副手进行空手挖树试验，随后 dig_unconfirmed，并未修复接口故障。执行器现会在 API 调用前拒绝将武器/工具装备到副手，主手装备与盾牌副手保持允许；提示词同步禁止此类试验。
