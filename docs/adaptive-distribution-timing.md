# 任务耗时采样与 Distribution 提前分发

## 数据

- `data/task-timing-samples.jsonl`：脚本开始、节流后的进度、正常/失败结束、分发耗时、预取决策、实际衔接等待。超过约 5 MB 轮转为 `.previous`。
- `data/task-timing-model.json`：有界历史样本与单位工作耗时，原子写入，重启加载。每种脚本/工具等级/维度/工作模式分别学习，并在缺少同类数据时使用较粗粒度历史。
- 不保存凭据、完整模型提示词或 Reflection。失败、取消、警告结束均记录，不能训练成“成功完成任务”的时长。

## 模型

1. 工作量 Q：采集还缺的资源数、台阶数、移动距离、洞室施工单元、熔炼数量等。鱼骨为“主道长度 + 全部左右支巷长度”，恢复任务减去已记录的完成量，主道结束不等于整个矿道结束。
2. 历史完成样本足够且工作量有变化时，用近期加权线性回归拟合 `T = 启动开销 + 单位工作耗时 × Q`。不满足拟合条件时使用实测单位耗时中位数；尚无数据则使用标记为 bootstrap 的默认值。
3. 执行中根据真实进度更新速度：`新单位耗时 = 0.65 × 旧值 + 0.35 × 本段实测值`，以剩余工作量估算剩余时间，优先于历史预测。
4. 分发时长包括输入整理、模型生成、结果校验与计划保存，按模型统计最近成功请求的均值和 P90。较慢失败请求影响近期拥堵提前量，但不算成功样本。
5. 当现有普通工作队列的剩余时间偏低估计不大于 `Distribution P90 + 2 秒衔接余量` 时，提前请求下一份计划。执行中的速度估计默认取 0.8 倍剩余时间作为较早触发值；这是调度余量，不是统计置信区间。

## 执行约束

- 当前脚本继续运行，未来计划只入队；鱼骨不因预取中断，成功完成后直接开始队首工作。
- 普通队列中的其余工作也计入预测，避免每个小动作都请求模型。同一队尾只预取一次；空闲唤醒与提前请求共用生成和入队过程，避免重复入队。
- 失败、危险、死亡、网络续跑或人工提示使依赖旧条件的预取作废。剩余条件变更由原有失败恢复/人工提示机制处理。
- 冷启动的采掘任务先等待真实进度；明显停滞时不继续倒数成“即将完成”，预测不充当任务超时或取消条件。
- GUI 工作队列下显示预计剩余、分发均值/P90、提前量、样本量、预取状态和上次实际衔接等待。现有 token 统计保持独立。

目标是降低正常收尾后的模型等待；突发危险、接口失败、模型耗时长尾与尚未观测的地形变化仍可能造成等待，不能保证任何情况都零空闲。
