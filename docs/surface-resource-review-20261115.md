# 地表资源检索与采集修复记录

日期：2026-11-15，北京时间。对应用户反馈：皮革应寻找牛、马等来源；近处甘蔗漏采，机器人反复走开。

## 已确认原因

1. `targets.item: "leather"` 表示背包最终需要的产物，不是实体检索名。旧实现确实只向实体接口查询 `cow`，漏掉其他皮革来源；并非真的用 `leather` 作为动物名检索。
2. 搜索接口曾经返回附近甘蔗：机器人 `[-285.5,63,208.5]`，最近甘蔗 `[-286,63,208]`，距离约0.7格，摘要共20段。这个观测来自本轮审查早期，不是部署后新增收获。问题位于发现之后的移动和采集链路。
3. 原生可通行集合漏了甘蔗，导致它既被当作障碍，也可能被当作实体落脚支撑；JS空间观察器另外将沙子、沙砾排除在支撑之外，岸边判断与实际地形不一致。
4. 地表节点的 `resourcesSkipped` 将一次不可达长期保留；后续换位置也会继续跳过旧目标。每次采集后又要求返回旧探索节点，增加折返。
5. 默认地表高度64导致已经处于露天地表的Y63岸边仍尝试挖阶梯上行，可能离开眼前资源。
6. 旧动物采集使用旧朝向攻击流程，未复用现有战斗脚本的即时瞄准与目标刷新。
7. 部署后额外确认：Tac保护任务的执行事件会覆盖Distribution持久化的普通任务，重启时原采集任务可能被 `survive` 替代。这个衔接错误也已修复。

接口契约已对照工作区的公开API参考实现：`docs/references/api-session.js` 的定向 `find_blocks` 返回坐标数组；无类型查询返回摘要对象。`get_entities` 的 `types` 支持实体名称或类别。没有读取世界存档。

## 修改

- 新增 `native/agent/surface.cpp`，由C++按产物映射来源。皮革搜索牛、哞菇、马、驴、骡，并复用战斗脚本瞄准、攻击和掉落物收取；只按实际背包变化记录皮革收益。
- 如果公开实体数据提供幼年、驯服、主人、命名标志，跳过对应动物。本机参考接口未承诺提供全部这些字段，因此不能据此声称能普遍识别所有已驯服动物。
- 甘蔗定向搜索，按柱归并并优先近处；从根上方一格收割，保留根。旧的永久不可达标记不再阻断地表资源重试。视线/距离失败时尝试其他有支撑的位置；仍不可达则记录坐标与原因，后续探索优先靠近目标。
- 非实体植物不套用石壁挖掘的邻水阻断；采收后按实际库存核验收益。单格甘蔗保留生长。
- 统一甘蔗等作物的可通行分类，修正沙质岸边支撑判定；Y63露天干燥岸边按实际高度工作。
- 采集位置发生变化后从新位置继续扫描，不强制回到旧节点。
- 新增资源观察日志，区分发现、收割、延后及狩猎尝试和真实增量。
- Distribution事件处理排除Tac与死亡恢复任务，防止保护任务覆盖普通工作的续跑记录、清除原工作失败原因。停止Worker后，已用部署前队列证据恢复同一个 `surface-gather-4` 任务及原调查ID，并保存恢复前记录。

主要文件：`native/agent/surface.cpp`、`native/agent/engine.hpp`、`native/agent/exploration.cpp`、`native/agent/combat.cpp`、`src/core/spatial-observer.js`、`src/native/distribution.js`、`src/debug/runtime-worker.js`。

## 仍需实机确认

自然遇到成熟甘蔗或动物后，确认采集事件对应实际库存增长；继续观察旧调查区域能否顺利拓展。此修复不代表附魔材料已齐，也不代表附魔目标已完成。

## 附魔设施与可选分支补充

复查发现，旧的共享方块摘要半径只有16格，而且把所有方块类别合并后截断为12项；因此附近的附魔台/书架可能没有进入 Distribution 输入。设施交互脚本本身只在收到附魔任务后才调用 `findBlocks`，不会在地表采集阶段主动探测附魔设施。

现已将公共方块观察半径扩大到32格，并在摘要中保留独立的 `visibleBlocks.facilities`（附魔台、书架、工作台、熔炉、箱子）列表。`build_enchanting_area` 未指定中心时，C++先搜索32格内现成附魔台，再搜索附近书架并直接复用，不会强制开新房间。相关设施复用回归已加入，当前附魔设施与上下文测试共15项通过。

附魔现在是可选分支：脚本默认 `optional:true`，最长运行时间默认3分钟；达到上限返回已完成物品并结束，书架和剩余附魔不再阻塞采集、采矿或生存。镐、剑、护甲仍按顺序尝试，已完成部分按真实 `enchantments` 保留。
