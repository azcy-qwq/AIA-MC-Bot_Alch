## 具体改进

1. **几何判定统一**：`passable` 与真正的 `air` 分开。落叶、杂花、花瓣等可穿行覆盖物不再成为台阶支撑；放置和挖掘仍用真实空气判定，避免覆盖物被当成空方块直接放置。
2. **探索局部恢复**：恢复任务时记录真实所在节点。候选移动只走到一半，也从实际落点继续；失效 DFS 父节点只淘汰对应回退边，再尝试其他祖先，不丢弃整个调查和已有进度。
3. **容量与装备维护**：目标堆叠还有空间时继续采集；不在没有容量时破坏该目标资源。补齐明确为空的护甲栏，选择随身最高等级，不替换已穿装备。已经满足采集数量时先结束，避免维护压缩资源后又误认为缺料。
4. **设施靠近顺序**：先到已记录工作区入口或设施旁的候选站位，再验证设施、打开容器。保留真实转移后的背包数量核对。
5. **服务端动作衔接**：`busy` 是请求未开始执行的拒绝，待公开状态表明锁释放后才重发；网络等不确定执行结果没有因此被统一盲重试。没有加任务时长超时。
6. **分发修复状态**：普通前置条件 warning 会清除“直接精确续跑”标记，让下一次分发进入修复同一目标的分支。失败信息、配方缺口和可清理物品名单保持简短且一致。

涉及 C++ 的 `engine.hpp / engine.cpp / navigation.cpp / exploration.cpp / survival.cpp / workshop.cpp / work.cpp`，以及 JS 的空间摘要、Distribution 状态和精简上下文。
